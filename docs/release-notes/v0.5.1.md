> **本版取代已撤回的 `0.5.0`。** `0.5.0` 的面板里倒计时在长假（例如 2026 年春节连休
> 9 天）会整段消失，`0.5.1` 修掉了它；`0.5.0` 已从 npm 撤回，版本号不再复用。

<h3 id="cn-v0.5.1">修复</h3>

- **长假期倒计时消失**：`0.4.0` 修这个问题时只改了 host 一侧——`pricing.js` 在调度带节假日例外时把「逐日推进找下一次时段切换」的上限从 8 天放宽到 32 天，而浏览器半的同构实现仍是写死的 8 天。于是两侧不一致：2026 年春节连休 9 天，从节前最后一个高峰窗口结束（2 月 13 日 18:00）起，客户端在 8 天内找不到下一次切换，胶囊上的「剩余时间」整段消失；host 在同一时刻却能算出 11.6 天后那次高峰。真实节假日数据实测：春节区间有 108 个采样点两侧不一致。现在客户端与 host 逐行同构；复核结果：**2026 全年逐小时**（两条内置条目，共 **17520** 个采样点）与三个高发窗口（春节 / 国庆 / 平常一周，半小时步长，共 **4230** 个采样点）**差异均为 0 处**，且全年没有任何时刻算不出下一次切换。
- **手工输入 provider 时输入框失焦**：条目列表按供应商分组，而分组键就是 provider 的值本身——用户正在输入它，于是每击一键 key 就变，React 把整棵子树拆掉重建，输入框被换成新的 DOM 节点，焦点与表单草稿一起丢（这也解释了为什么只在 provider 上出现：model 不参与分组键）。含正在编辑条目的分组现在改用条目 id 作键，输入期间不再重挂。
- **provider / model 两列与下一行「币种 / 峰谷规则」错位**：两行原本各写一套网格，路由那行为了收窄先后用过写死像素与「两列 + 空列」的配比，前者在窄窗口下溢出卡片（看起来像两个框叠在一起）、后者与下一行对不齐。现在两行**直接共用同一个 `.tf_grid2`**，对齐由结构保证。
- **组合框被内容撑破轨道**：官方 `Menu` 把 anchor 包在 `display:inline-flex` 的收缩盒里，该包装的 `min-width:auto` 以内容宽度为下限，可以越过网格轨道盖到相邻字段上（实测 provider 153px 而 model 撑到 227px，两框叠在一起、间距消失）。只写 `max-width:100%` 压不住（内容下限优先于 max-width），补上 `width:100%` 之后两列才真正等于轨道宽度。

<h3 id="cn-v0.5.1">改进</h3>

- **币种与峰谷规则改用与 provider / model 同一套控件**：新增只读组合框 `SelectField`，替代原来的原生 `<select>`——原生弹出列表由系统绘制，浅色高亮与字体都不跟随主题，和旁边的组合框摆在一起很跳。现在两者同高、同描边、同底色、同一个箭头、同一个半透明 `Menu`，整块取值区都能点开。

<h3 id="en-v0.5.1">Fixes</h3>

> **This release supersedes the withdrawn `0.5.0`.** In `0.5.0` the countdown vanished for the whole of a long holiday (the 2026 Spring Festival is nine days off); `0.5.1` fixes it. `0.5.0` has been unpublished from npm and its version number will not be reused.

- **The countdown disappeared during long holidays**: the 0.4.0 fix only touched the host half — `pricing.js` widened the day-by-day search for the next tariff switch from 8 to 32 days when a schedule carries holiday exceptions, while the browser's mirror implementation kept a hard-coded 8. The two halves then disagreed: with the 2026 Spring Festival's nine consecutive days off, starting from the end of the last peak window before it (Feb 13, 18:00), the client found no next switch within 8 days and the pill's "remaining time" vanished entirely, while the host computed the next peak 11.6 days out. Measured against the real holiday data, 108 sampled instants differed across the Spring Festival window. The client is now line-for-line identical to the host; a re-check over **every hour of 2026** (both built-in entries, **17,520** sampled instants) and over three high-risk windows (Spring Festival / National Day / an ordinary week, half-hour steps, **4,230** sampled instants) shows **zero differences**, with no instant in the year failing to produce a next switch.
- **The provider input lost focus while typing**: the entry list groups by provider and the group key *is* the provider value — which the user is typing. Every keystroke changed the key, React tore down and rebuilt the subtree, and the input became a new DOM node, losing focus and the form's drafts (this also explains why only the provider field was affected: the model does not participate in the group key). A group holding the entry being edited now keys on the entry id, so it no longer remounts while typing.
- **provider / model no longer lined up with the "currency / peak rule" row below**: each row had its own grid, and the route row had been narrowed first with hard-coded pixels (which overflowed the card in a narrow window and looked like two overlapping boxes) and then with a two-columns-plus-spacer ratio (which did not line up with the row below). Both rows now **share the same `.tf_grid2`**, so alignment is guaranteed by structure.
- **A combobox could burst out of its track**: the built-in `Menu` wraps its anchor in a `display:inline-flex` shrink-to-fit box whose `min-width:auto` uses the content width as a floor, letting a wider field cross its grid track and cover the neighbouring one (measured: provider 153px while model swelled to 227px, overlapping and eating the gap). `max-width:100%` alone cannot stop it — the content floor outranks max-width — so `width:100%` is required for the columns to actually equal their tracks.

<h3 id="en-v0.5.1">Improvements</h3>

- **Currency and peak/off-peak rule now use the same control as provider / model**: a new read-only combobox, `SelectField`, replaces the native `<select>`, whose popup list is drawn by the system — light highlight and font both ignore the theme, which looks jarring next to the neighbouring combobox. Both now share height, stroke, fill, chevron and the same translucent `Menu`, and the whole value area is clickable.

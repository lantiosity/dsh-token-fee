<h3 id="cn-v0.6.1">数据</h3>

- **补充 2027 年法定节假日与调休**：取自[国务院办公厅关于 2027 年部分节假日安排的通知](https://www.gov.cn/zhengce/content/202611/content_7085101.htm)（国办发明电〔2026〕10号），新增 29 天假期、5 天调休上班。`data/cn-holidays.json` 现覆盖 **2026–2027**（合计 62 天假期、11 天调休），并保留两个年度的通知出处。新增用例逐条对照通知，并用内置规则实测 2027 春节/国庆确实按空闲判定。

<h3 id="cn-v0.6.1">修复</h3>

- **保存价目表会清空用户文件里的汇率（数据丢失）**：设置页保存是整份覆盖写，`buildSavePayload` 返回了汇率但组件把它解构成条目数组后再取 `.exchangeRates`（恒为 `undefined`），一点保存就把 `token-fee.json` 里的 `exchangeRates` 删掉。现在组件传回整个返回体；host 端点另外兜底——请求体**没提** `exchangeRates` 时保留文件现有值，只有显式 `{}` 才清空。新增**组件级**用例真正驱动保存按钮并断言 `POST` 请求体（旧用例只测了 helper 的正确调用方式，因此没咬住真实路径）。
- **备选安装器装完 host 半即坏**：`scripts/install.mjs` 的复制清单漏了 `data/`，而 host 半在模块顶层同步读 `data/cn-holidays.json`，装出来的插件在装载期直接 ENOENT。现在复制清单与 `package.json#files` 对齐，`--check` 校验 `lib/`、`data/`、`cordis.patch.yml` 等运行时文件，安装后在同一进程里**真的 import** 安装副本；拆出 `install-lib.mjs` 以便测试，并识别用户手写的单引号 patch 记录（不再重复追加 insert）。
- **用户文件无效时的一次保存会覆盖成空表**：文件读不出来时有效层已回落到内置、编辑器草稿是空的，旧实现点保存就把整份文件覆盖成 `{"entries":[]}`。现在界面禁用「保存」与「恢复内置价目」并说明原因，host 返回 **409** 拒绝覆盖（`force` 才放行），写之前先刷新文件状态。
- **host 接受的合法文件在编辑器里保存即崩溃**：条目缺 `provider` / `currency` / 价格桶时 host 会补默认值，但编辑器草稿直接用原始层字段 `trim()`，抛 `TypeError` 且 `busy` 永远停在 true（按钮卡在「保存中…」）。现在 `adoptPricing` 按 host 归一化规则补齐默认值，整个保存流程移入 `try`。
- **DST 时区的倒计时会错 21–24 小时**：`wallClockToTimestamp` 只返回一个解、候选集只有「零点 / 窗口起止」，春令时被跳过的那一小时里没有对应时刻、秋令时重复的那一小时只取到一个解。现在墙上边界取**全部解（0/1/2 个）**，候选集加入**偏移跳变瞬间**，两半同步修改并加「春令时 30 分钟 / 秋令时 90 分钟」与两半逐点对照用例。默认 `Asia/Shanghai` 不受影响。
- **改价格或备注会作废所有会话检查点**：表指纹原来对整份条目做哈希，改一个单价也要让 DSH 从 `seq 0` 重折所有会话。现在指纹只覆盖折叠语义（条目顺序/条数、`provider`/`model`、有没有 `offPeak`、解析后的调度）；改价格/备注/币种只刷新展示。
- **未知字段静默变成另一种语义**：`provder` 拼错会让 `provider` 回落成通配 `*`（把某供应商的价套到所有供应商），`cache_read` 会被静默按 0 计，`holiday` 会被静默忽略。现在条目 / 价格块 / 调度都有白名单校验，当场报错并点名未知字段。
- **同身份条目静默遮蔽**：同一层内两条 `(provider, model, currency)` 相同的条目会让后一条静默覆盖前一条，而编辑器两条都显示（「改了价却没生效」）。现在保存时直接报错点名两条 `id`；跨层覆盖（用户层/配置层覆盖内置）仍然允许。
- **保存会「规整」用户文件**：平面条目（没有空闲价）原本用不到峰谷判定，但文件里已有的 `schedule` 引用会在保存后被一律写成 `null`。现在原样保留。
- **嵌套子代理用量漏计**：框架的 `subagentCatalog` 只登记直接子会话，孙代消耗不在父会话账上，而文档声称「覆盖整棵子树」。端点现在递归收集整棵子树（深度上限 4、`seen` 防环），卡片标出「含 N 个嵌套」。
- **子代理口径的两处静默**：超过 64 个直接子代理时多余的 id 被静默丢弃；确实没产生用量的子代理被显示成「读不到用量」。现在响应带回 `truncated` 并在面板提示，`rows: []`（未产生用量）与 `null`（读不到）分别呈现。
- **空面板吞掉子代理错误**：本会话没有用量、子代理接口又失败时，面板只说「还没有产生计费用量」。现在错误与未计入数照常显示。子代理端点异常也改为就地返回 500 + 结构化 JSON（不再依赖 webserver 的 400 纯文本兜底）。
- **破坏性操作无确认**：「恢复内置价目」会删除用户手写的 `token-fee.json`，现在先确认。
- **未保存草稿无声丢失**：切到「明细」标签或关面板会卸载编辑器，刚改的内容消失；现在按 `pricing` 句柄暂存、重新挂载即恢复，并提示「有未保存的修改」。面板内浮层展开时按 Esc 只关浮层，不再连面板一起关。
- **引用 `cordis.yml` 规则的条目无法保存**：编辑器规则名只取「内置 + 文件草稿」，本地校验会判定「引用的规则已不存在」而阻止保存。现在合并层的规则名也纳入候选。
- **投影 schema 过宽**：恢复检查点时结构不符会被静默接受（`{}`、缺 `route`/`last`、非法 `tariff`），把「抛错→整段重折」降级成「从错误起点继续折」。现在严格校验，并在同一步骤重放相同用量时短路返回原状态（少发一帧投影、少写一次检查点）。

<h3 id="cn-v0.6.1">性能</h3>

- **倒计时重算从每次 1.2 万次 `Intl.formatToParts`（~55 ms）降到 36 次（<1 ms）**：随包节假日跨 2026–2027 时，扫描上限被例外跨度顶到 400 天且先把所有候选枚举完。现在逐日提前返回、例外日期转 `Set` 并按调度缓存、切换点按条目缓存；缓存命中后每次只剩 1 次 `Intl`。两半都有成本上界用例（冷调用 <200 次、热调用 ≤2 次）。
- **路由建议不再拖住价目表**：`llm.listModels` 可能很慢，却 `await` 在 `GET /api/token-fee/pricing` 里。现在拆成独立端点 `GET /api/token-fee/routes`（30 秒 TTL + 后台刷新），价目表只读缓存；编辑器打开时自己懒加载建议。
- **子代理轮询**：端点改用 `projectionMode: 'none'` 并自己折 `subagent/catalog` 事件（不再让框架为每个子会话水合所有投影），加 2 秒 TTL 缓存；客户端加在途保护、页面不可见时暂停、连续读数不变时退避。

<h3 id="cn-v0.6.1">其他改进</h3>

- 金额按币种标准小数位显示（JPY 0 位、CNY/USD 2 位、BHD 3 位）。
- 时间戳非法（`NaN`/`Infinity`）时不再抛 `RangeError`，按「没有可用计费状态」处理。
- 面板 aria 的金额口径与可见金额统一（都用含子代理的合计）。
- 跟踪式文档补齐：端点信任边界（本机进程）、fork 与子代理两种会话口径、两半「语义等价而非逐位相同」、`stateSchema`/`viewSchema` 只实现 `parse` 的显式假设、2027 数据源、兼容核对扩展到 `0.2.2-rc.3`。

<h3 id="cn-v0.6.1">工程</h3>

- **打 tag 即自动发布**：新增 `.github/workflows/release.yml`，推送 `v*` 标签后校验版本 → 跑发布闸门 → 用 npm **Trusted Publishing（OIDC）+ provenance** 发布 → 轮询 registry 确认上线 → 用本文件创建 GitHub Release。本版起不再需要人工 `npm publish`（也就绕开了 2FA 那道手工步骤）。手动触发该 workflow 只跑 `npm publish --dry-run` 冒烟。
- **发布闸门**：`npm run verify` 改由 `scripts/verify.mjs` 编排，进程级套件的「跳过」用退出码 77 与失败区分；`npm run verify:process` 为严格模式（跳过即失败）。CI 新增真跑 `dsh web` 的 `process` job 与 Windows 矩阵。
- 新增套件：组件级（真正驱动编辑器的保存/重置按钮）、安装器端到端（装完真的 import）、闸门语义。测试合计：pricing 73、host 51、client 127、installer 6、editor 7、闸门语义 2、进程级 9。

<h3 id="cn-v0.6.1">升级说明</h3>

- **无破坏性变更**，但有两处**有意的 fail-loud**：用户文件里出现未知字段（如 `provder`）、或同一层内出现两条 `(provider, model, currency)` 相同的条目时，本版会**报错并拒绝装载/保存**，而不是继续按错误语义计价。按报错信息改正即可（未知字段改名、重复条目合并成一条）。
- **2027 年节假日数据是装载期读取的**：升级后需重启 `dsh`（浏览器刷新不够）才会用上。
- 建议升级后确认：设置页保存一次价目表后 `token-fee.json` 里的 `exchangeRates` 仍在；有自定义 DST 时区的规则时倒计时显示正常。

<h3 id="en-v0.6.1">Data</h3>

- **Added China's 2027 public holidays and make-up workdays**, taken from the [State Council notice on the 2027 holiday arrangement](https://www.gov.cn/zhengce/content/202611/content_7085101.htm) (国办发明电〔2026〕10号): 29 holiday days and 5 make-up workdays. `data/cn-holidays.json` now covers **2026–2027** (62 holiday days, 11 make-up workdays) and keeps the source for both notices. <h3 id="en-v0.6.1">Fixes</h3>

- **Saving the price table wiped the user's exchange rates (data loss)**: the settings save is a whole-file overwrite; `buildSavePayload` returned the rates but the component destructured it into the entry array and read `.exchangeRates` off that array (always `undefined`), so one save deleted `exchangeRates` from `token-fee.json`. The component now passes the whole result, and the host endpoint also guards: an omitted `exchangeRates` **preserves** the file's current rates, only an explicit `{}` clears them. A new **component-level** test actually drives the save button and asserts the `POST` body (the old test only proved the helper was called correctly, so it never caught the real path).
- **The fallback installer produced a broken host half**: its copy list missed `data/`, while the host half reads `data/cn-holidays.json` synchronously at module load — the installed plugin failed with ENOENT at load time. The copy list is now derived from `package.json#files`, `--check` validates the runtime files (`lib/`, `data/`, `cordis.patch.yml`, …), the installer **really imports** the installed copy, the logic moved into a testable `install-lib.mjs`, and hand-written single-quoted patch entries are recognised (no duplicate insert).
- **One save could overwrite an unreadable user file with an empty table**: with the file unreadable the effective layer falls back to built-ins and the editor draft is empty. Saving is now disabled (with an explanation) in that state and the host returns **409** instead of overwriting (unless `force`), refreshing file state first.
- **A file the host accepts crashed the editor on save**: entries may omit `provider`/`currency`/price buckets (the host defaults them), but the editor called `.trim()` on raw fields, threw a `TypeError`, and left `busy` stuck forever. `adoptPricing` now fills the host's defaults, and the whole save flow runs inside `try`.
- **DST time zones could show a countdown off by 21–24 hours**: only one wall-clock solution was computed and the candidate set was just midnight/window edges, so the hour skipped by spring-forward had no instant and the hour repeated by fall-back picked a single solution. Wall boundaries now yield **all** solutions (0/1/2) and the candidate set includes **UTC offset transitions**; both halves were changed together with tests for a 30-minute spring case and a 90-minute fall case. `Asia/Shanghai` is unaffected.
- **Editing a price or note invalidated every session checkpoint**: the table fingerprint hashed the whole entry set, so a single price change forced DSH to refold every session from `seq 0`. The fingerprint now covers fold semantics only (entry order/count, `provider`/`model`, whether `offPeak` exists, the resolved schedule); price/note/currency edits only refresh the display.
- **Unknown fields silently changed the meaning**: a typo like `provder` made `provider` fall back to the `*` wildcard (pricing one vendor's rates for all), `cache_read` was counted as 0, `holiday` was ignored. Entries, price blocks and schedules now validate a key whitelist and name the unknown fields.
- **Duplicate identities shadowed each other silently**: two entries with the same `(provider, model, currency)` in one layer meant the later one silently won while the editor showed both (“I changed the price but nothing happened”). Saving now errors and names both `id`s; cross-layer overriding (user/config over built-in) still works.
- **Saving “normalised” the user's file**: flat entries (no off-peak price) don't need a schedule for billing, but an existing `schedule` reference was rewritten to `null` on save. It is now preserved.
- **Nested subagent usage was missed**: the framework's `subagentCatalog` only registers direct children, so grandchildren were never billed while the docs promised “the whole subtree”. The endpoint now collects the whole subtree recursively (depth limit 4, `seen` guard) and marks rows “incl. N nested”.
- **Two silent subagent behaviours**: ids beyond the 64-per-query limit were dropped silently, and subagents that genuinely produced no usage were shown as “unreadable”. The response now carries `truncated` (reported in the panel), and `rows: []` (no usage) is rendered separately from `null` (unreadable).
- **An empty panel swallowed subagent errors**: with no usage of its own and a failing subagent endpoint, the panel only said “no billed usage yet”. Errors and the not-counted figure are shown now; the subagent endpoint also turns its own exceptions into a 500 with structured JSON instead of relying on the webserver's plain-text 400 fallback.
- **Destructive action without confirmation**: “Restore built-in pricing” deletes the user's hand-written `token-fee.json`; it now asks first.
- **Unsaved drafts were lost silently**: switching to the “breakdown” tab or closing the panel unmounted the editor. Drafts are now stashed per `pricing` handle and restored on remount, with an “unsaved changes” hint; Escape with a dropdown open only closes the dropdown.
- **Entries referencing a `cordis.yml` schedule could not be saved**: the editor's schedule names only covered built-ins plus the file draft, so local validation claimed the referenced rule no longer existed. The merged layer's schedule names are included now.
- **The projection schema was too loose**: a restored checkpoint with a wrong shape (`{}`, missing `route`/`last`, invalid `tariff`) was accepted silently, downgrading “throw → refold” into “continue from a wrong point”. It is strictly validated now, and replaying identical usage for the same step short-circuits to the same state (no wasted projection frame or checkpoint write).

<h3 id="en-v0.6.1">Performance</h3>

- **The countdown went from ~12k `Intl.formatToParts` calls (~55 ms) per second to 36 calls (<1 ms)**: with shipped holidays spanning 2026–2027 the scan limit was pushed to 400 days and every candidate was enumerated before sorting. It now returns early day by day, turns holiday dates into `Set`s cached per schedule, and caches the switch instant per entry; a cache hit costs one `Intl` call. Both halves have a cost bound test (cold <200 calls, warm ≤2).
- **Route suggestions no longer hold up the price table**: `llm.listModels` can be slow, yet `GET /api/token-fee/pricing` awaited it. It now lives on its own `GET /api/token-fee/routes` (30 s TTL with background refresh) while the price table only reads a cache; the editor lazily loads suggestions when opened.
- **Subagent polling**: the endpoint uses `projectionMode: 'none'` and folds `subagent/catalog` events itself (no more hydrating every registered projection per child), with a 2 s TTL cache; the client gained in-flight protection, pauses when the page is hidden, and backs off while results are unchanged.

<h3 id="en-v0.6.1">Other improvements</h3>

- Amounts use each currency's standard fraction digits (JPY 0, CNY/USD 2, BHD 3).
- Non-finite timestamps (`NaN`/`Infinity`) no longer throw `RangeError`; they are treated as “no billing state available”.
- The panel's aria amount now matches the visible one (both use the total including subagents).
- Documentation caught up: endpoint trust boundary (local processes), the two session scopes (whole log vs suffix), “semantically equivalent rather than bit-identical” for the two halves, the explicit assumption that `stateSchema`/`viewSchema` only implement `parse`, the 2027 data source, and the compatibility check extended to `0.2.2-rc.3`.

<h3 id="en-v0.6.1">Engineering</h3>

- **Tag-driven publishing**: new `.github/workflows/release.yml` checks the version against the tag, runs the release gate, publishes with npm **Trusted Publishing (OIDC) + provenance**, polls the registry until the version is live, and creates the GitHub Release from this file. No manual `npm publish` (and no 2FA step) from this release on. Manually dispatching the workflow only runs `npm publish --dry-run` as a smoke test.
- **Release gate**: `npm run verify` is now orchestrated by `scripts/verify.mjs`, which treats a “skipped” process suite (exit code 77) differently from a failure; `npm run verify:process` is the strict variant (a skip fails). CI gained a `process` job that really runs `dsh web` and a Windows matrix.
- New suites: component-level (actually driving the editor's save/reset buttons), installer end to end (really importing the installed copy), and gate semantics. Test totals: pricing 73, host 51, client 127, installer 6, editor 7, gate semantics 2, process-level 9.

<h3 id="en-v0.6.1">Upgrade notes</h3>

- **No breaking changes**, but two **intentional fail-loud behaviours**: a user file containing unknown fields (e.g. `provder`), or two entries with the same `(provider, model, currency)` in one layer, now **errors instead of loading/saving** with the wrong semantics. Fix the name or merge the duplicate entries as the error says.
- **The 2027 holiday data is read at load time**: restart `dsh` after upgrading (a browser refresh is not enough).
- Worth confirming after upgrade: `exchangeRates` in `token-fee.json` survive a save from the settings page, and the countdown looks right for rules with custom DST time zones.

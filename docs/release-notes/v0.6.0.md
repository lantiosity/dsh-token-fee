<h3 id="cn-v0.6.0">新功能</h3>

- **子代理用量计入合计**：当前会话调用的子代理跑在各自的会话里，用量本来不在这条会话的账上。现在它们的消耗会**计入胶囊与合计**，并在明细里单独成组：每个子代理一行「标签 + 总 token + 费用」，点开才是它自己的按供应商/模型明细。有子代理时合计标题写成「合计（含子代理）」以作区分。嵌套子代理由各自的父会话计入，因此合计覆盖整棵子树；直接子代理由框架的子代理目录投影给出。
- **读不到就说清楚**：某个子代理的用量取不到时，卡片显示「读不到用量」，面板说明有几个未计入合计——少算的钱要说得出为什么少，不当成 0。**已知限制**：跑在 DSH 之外的后端（ACP、Codex、Claude Code 等）不产生 DSH 会话日志，其 token 无处可读，这类子代理只能显示 0。
- **汇率改用 `token-fee.json` 配置**：折算汇率从 `cordis.yml` 搬到用户价目文件，落成一层：

  ```json
  { "version": 1, "exchangeRates": { "USD": 7.2 }, "entries": [] }
  ```

  含义不变（1 单位该币种 = 多少展示币种）。文件按 mtime 热读，**改完不用重启 dsh**（打开「价格设置」页会重新拉取，胶囊刷新页面后更新）。层次顺序与价目表一致：内置 → 用户文件 → 插件配置，`cordis.yml` 里那份仍然有效并保留为管理员覆盖（同币种以配置为准，没写的沿用文件）。

<h3 id="cn-v0.6.0">修复</h3>

- **子代理全部显示「读不到用量」**：`tokenFee` 的投影视图是 `{ rows, route }` **对象**而不是裸数组，端点把整块当 `rows` 回给客户端，客户端的 `Array.isArray` 判定失败。同时把取数面收敛成官方那条：`sessionQuery.observeSession(id)`（框架枚举子会话的 `listChildren` 走的正是它），活会话与已结束会话统一处理，不再依赖「子会话在不在 `ctx.sessions` 里」或「会不会出现在会话列表里」。
- **子代理组标题显示 `NaNM`**：面板取了不存在的字段，改为子代理合计视图的 token 数。
- **子代理重复计算父会话的用量**：DSH 以「新建会话 id + 把父会话事件当种子写进子会话日志」启动 fork 与子代理会话，整段折叠会把父会话的钱在每个子会话里各重算一遍——实测一条会话带四个子代理时，四张卡片各自显示同样的 `1068.6M token`，合计被放大三个数量级（真实值 1.37M）。现在只折 `seq >= inheritedEventCount` 的后缀，并保留种子里的 `request/header`（它决定路由，整段跳掉会让子会话自己的请求折不出任何行）。
- 只改汇率不再作废会话检查点：汇率只影响展示、不影响折叠语义，因此不参与折叠指纹，但仍会通知订阅者刷新折算合计。
- 设置页保存价目表不再顺带清空汇率：保存是整份覆盖写，客户端现在把**文件层**那份汇率原样带回（不是生效值，否则会把 `cordis.yml` 的管理员配置固化进用户文件）。

<h3 id="cn-v0.6.0">升级说明</h3>

- **无破坏性变更**：`cordis.yml` 里的 `exchangeRates` 继续生效；旧格式（只有 `entries` 数组、或不含 `exchangeRates` 的文件）照常读取。
- `0.5.2` 曾打过标签但**没有发布到 npm**，本版包含它的全部修复（零条目可保存、Windows 上连点保存的 `EPERM`、状态版本取模、节假日数据缺 `sets` 拒绝装载、`1000K` 显示修正等）。
- 由节点自身的 `subagentCatalog` 提供子会话清单：未装载子代理插件时这一块自然不出现，不影响其它功能。

<h3 id="cn-v0.6.0">内部</h3>

- 子代理取数只依赖两个内部面：客户端 `useProjection('subagentCatalog')` 与 host `ctx.sessionQuery.observeSession`，都写成**可选**（缺失时降级为「读不到」并给出原因代码，不抛错）。
- 测试：pricing 63、host 42、client 116、进程级 9。

<h3 id="en-v0.6.0">New features</h3>

- **Subagent usage counts toward the total**: subagents called by this session run in their own sessions, so their usage was not on this session's bill. It is now **folded into the pill and the total**, and gets its own group in the breakdown: one row per subagent with its label, total tokens and cost, expanding to that subagent's own provider/model detail. When any are present the total is labelled "Total (incl. subagents)". Nested subagents are counted by their own parent, so the total covers the whole subtree; direct children come from the framework's subagent catalog projection.
- **Unreadable means explained**: if a subagent's usage cannot be read, its card says so and the panel states how many were left out of the total — a shortfall should say why, not read as zero. **Known limitation**: backends running outside DSH (ACP, Codex, Claude Code, …) produce no DSH session log, so their tokens cannot be read and such subagents can only show 0.
- **Exchange rates now live in `token-fee.json`**: the conversion table moved from `cordis.yml` into the user pricing file, as one more layer:

  ```json
  { "version": 1, "exchangeRates": { "USD": 7.2 }, "entries": [] }
  ```

  The meaning is unchanged (one unit of that currency equals how many display-currency units). The file is read by mtime, so **no dsh restart is needed** (opening the pricing page refetches; the pill updates on a page refresh). Layer order matches the price table — built-in → user file → plugin config — and the `cordis.yml` copy still works as the administrator override (config wins per currency, currencies it omits fall back to the file).

<h3 id="en-v0.6.0">Fixes</h3>

- **Every subagent showed "usage unavailable"**: the `tokenFee` projection view is a `{ rows, route }` **object**, not a bare array, and the endpoint forwarded it whole as `rows`; the client's `Array.isArray` check then failed. The read path was also collapsed onto the official one — `sessionQuery.observeSession(id)`, the same call the framework's own `listChildren` uses — which treats live and finished sessions alike and no longer depends on whether a child sits in `ctx.sessions` or shows up in the session list.
- **The subagent group header read `NaNM`**: the panel used a field that does not exist; it now uses the subagent subtotal's token count.
- **Subagents recounted the parent's usage**: DSH starts a fork or subagent session by minting a new id and writing the parent's events into the child's log as a seed, so folding the whole log replayed the parent's spend inside every child — with four subagents, all four cards reported the same `1068.6M` tokens and the total was inflated by three orders of magnitude (the real figure was 1.37M). Only `seq >= inheritedEventCount` is folded now, keeping the seeded `request/header` because it establishes the route (dropping the whole seed leaves a child's own requests with no route and yields no rows at all).
- A rate-only edit no longer invalidates session checkpoints: rates affect display, not folding, so they stay out of the fold fingerprint — while still notifying subscribers so the converted total refreshes.
- Saving the price table from the settings page no longer wipes the rates: the save is a whole-file overwrite, and the client now carries the **file layer's** rates back (not the effective ones, which would bake the administrator's `cordis.yml` values into the user file).

<h3 id="en-v0.6.0">Upgrade notes</h3>

- **No breaking changes**: `exchangeRates` in `cordis.yml` keeps working, and older files (an `entries` array, or no `exchangeRates`) still load.
- `0.5.2` was tagged but **never published to npm**; this release carries all of its fixes (zero-entry saves, the Windows `EPERM` on rapid double saves, the state-version modulo, refusing to load holiday data without `sets`, the `1000K` formatting fix, and more).
- The child list comes from DSH's own `subagentCatalog` projection: with the subagent plugin unmounted that section simply does not appear, and nothing else is affected.

<h3 id="en-v0.6.0">Internals</h3>

- Subagent reading depends on exactly two internal surfaces — the client's `useProjection('subagentCatalog')` and the host's `ctx.sessionQuery.observeSession` — both treated as **optional** (a missing one degrades to "unreadable" with a reason code instead of throwing).
- Tests: pricing 63, host 42, client 116, 9 process-level.

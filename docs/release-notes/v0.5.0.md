<h3 id="cn-v0.5.0">功能</h3>

- **多币种并列显示**：此前**合计、供应商行与胶囊**都只累加展示币种，其他币种只在它自己的模型卡片上出现——于是合计偏小且无从察觉，而一个只跑过美元路由的供应商会在行尾显示成 `¥0.00`。现在每种币种独立累加并**并列显示**（`¥1.23 + US$0.56`），展示币种排在前面，其余按金额降序。胶囊、合计、明细里的每个供应商行都按同一口径累加。
- **可选汇率折算**：新增配置键 `exchangeRates: { USD: 7.2 }`，含义是**1 单位该币种等于多少展示币种**（方向就是「相对展示币种」，换算时直接相乘）。所有有金额的外币都配了汇率时，额外给出一个 `≈` 折算合计。
- **缺任一外币汇率就完全不给折算合计**，并在明细里点名缺哪个币种。半个合计比没有合计更危险：它看起来像「都算完了」，实际漏了一种币。
- 折算合计用 `≈` 而不是 `=`：它是按你配置的汇率算出的参考值，不是任何一方的实际入账金额，也不该被当成官方数字。并列展示不依赖汇率，因此没有汇率时每种币的用量照样一个不丢。
- **升级提示**：如果你有非展示币种的价目（例如人民币展示 + 美元条目），升级后合计的**含义**会变——此前被丢掉的外币现在会并列显示出来。这是修正而非行为回归，但数字看起来会变。
- **价目条目按供应商折叠**：自定义与只读内置两段都按供应商分组，**默认折叠**成一张「供应商 · 条数」清单。正在编辑的条目所在分组强制展开——否则点了「编辑」或「新增条目」却看不到表单。
- **列表按供应商、模型名的首字母排序**：比较忽略大小写，但**分组不忽略**（provider id 大小写敏感，`Beta` 与 `beta` 是两条路由，不会被并成一组）。用码位而不是 `localeCompare` 比较，因此同一份配置在不同 locale 的机器上顺序一致。排序与折叠只作用于展示：底层数组顺序仍决定同优先级通配条目的匹配顺序，编辑与删除仍按原始下标回写。
- **点「新增条目」时新条目排在第一位**，不再追加到最后：它的 `provider` / `model` 都是空的，本来就该在最显眼处填写；条目一多，追加到末尾会让人还得往下滚才能找到那个刚出现的编辑框。
- **明细面板每个模型默认折叠**：折叠态是「模型名 · 总 token · 费用」，点一下才展开四个计费桶各自的 token 数与金额。一个会话常有十几个模型，先摆出总量、要看细节再展开，面板一打开就能扫完总额。
- **折叠时仍显示警示徽章**（未记录时段、缺少价目条目）——它们关乎账单准不准，不该藏在一次点击之后。中性的身份徽章（区分峰谷、通配条目）随明细一起收起。
- **价格设置面板收窄到 440px**（原 560px）。规则表单的排布同时调整：**时区与法定节假日并排一行，高峰星期独占一行**。后者不是随手排的——7 个星期按钮本身要 214px，挤在两列网格的一列里会把面板宽度下限顶到 460px 以上；独占一行后下限回到四列单价表那边（约 380px）。

<h3 id="cn-v0.5.0-fixes">修复</h3>

- **折叠后的卡片下半部分是一整块空白**：徽章容器是 `display:inline-flex`，一个徽章都没有时也会生成一个行盒（约一行高 + 6px 上边距）；折叠态只剩 18px 表头，这块空白就占了近一半高度，表头看着也就没居中。现在徽章先收成数组、**只在真有徽章时才渲染容器**。
- 同一处还有两个成因：表头用 `align-items:baseline` 而箭头是 `inline-flex`（参与基线对齐时以底边作基线，会把整行撑高、文字偏上），以及金额原先靠表头的 `space-between` 贴右、换成按钮后没接上。现在表头纵向居中、箭头改 `flex`，模型名 `flex:1` 配省略号、金额 `flex:none` 自然贴右成一列。
- **供应商行只显示人民币**：同一供应商只累加展示币种，于是**只跑过美元路由**的供应商算出 0，行尾渲染成 `¥0.00`。现在每个供应商也按币种分别累加，行尾与总计同一套规则。
- 清掉 `.tf_model` / `.tf_cardAmount` 的**重复 CSS 规则**（后写的旧规则会覆盖新规则）。

<h3 id="cn-v0.5.0-docs">文档与内部</h3>

- **兼容性核对扩展到 DSH `0.2.1-rc.2`**：在 0.2.1 线的 7 个 tag（`alpha.1`–`alpha.5`、`rc.1`、`rc.2`）上逐项复核本插件依赖的全部契约面，全部未变（`Menu`/`Button` 的 `.tsx` 在两版之间一字未改）。0.2.1 线带来两条**视觉**边界：官方统计胶囊拆成每条目一枚（`activity` / `usage`），以及胶囊圆角由 `999px` 改为 `var(--dsw-radius-sm)`（8px）。前者对本插件无影响（dock 容器仍负责行布局，条目间距仍 12px）；后者**有意不跟随**——`--dsw-radius-sm` 在 `0.2.0-rc.2` 上就已是 8px、无法当版本标记，而 `latest` 仍是 `0.2.0-rc.2`（官方全圆角），此时改成 8px 反而与同排的官方胶囊不一致。方法与结论记在 [`docs/dsh-integration.md`](../dsh-integration.md)。
- **内置价目改为单一数据源**：条目由 `DEEPSEEK_BUILTIN_MODELS` 派生，价格块只出现一次，条目说明写明它同时覆盖「官方 API」与「DeepSeek 账号」两条路由。**这不是新增覆盖能力**——账号路由在 0.4.0 时就已由 provider 别名命中，本次只是把数据源单一化，并把这件事写进面板里的条目说明。
- README 的多币种与明细说明、`docs/configuration.md` 新增的「按供应商折叠」「明细面板按模型折叠」「规则表单的排布」三节，都记录了上述行为与它们各自的设计理由。

<h3 id="en-v0.5.0">Features</h3>

- **Currencies are shown side by side**: previously the **total, the provider rows and the pill** accumulated only the display currency; any other currency appeared solely on its own model card — so the total was simply too small with no way to notice, and a provider that had only ever run a USD route showed `¥0.00` at the end of its row. Now every currency is accumulated independently and shown **side by side** (`¥1.23 + US$0.56`), display currency first and the rest by amount, largest first. The pill, the total and every provider row in the breakdown use the same rule.
- **Optional rate conversion**: the new `exchangeRates: { USD: 7.2 }` config key means **one unit of that currency equals N units of the display currency** (the direction is already "relative to the display currency", so conversion is a plain multiplication). When every foreign currency with an amount has a rate, an additional `≈` converted total is shown.
- **If any foreign currency has no rate, no converted total is shown at all**, and the breakdown names the missing currencies. Half a total is more dangerous than none: it looks complete while quietly omitting a currency.
- The converted total uses `≈`, not `=`: it is a reference figure computed from the rates you configured, not what anyone actually charged. Side-by-side display does not depend on rates at all, so without rates no currency's usage is lost.
- **Upgrade note**: with prices in a non-display currency (CNY display plus, say, USD entries) the **meaning** of the total changes after upgrading — foreign currency that used to be dropped is now shown alongside. That is a correction rather than a regression, but the number will look different.
- **Pricing entries fold by provider**: both the custom and the read-only built-in section group by provider and **start collapsed** as a "provider · count" list. A group holding the entry being edited is forced open — otherwise clicking "Edit" or "Add entry" would show no form.
- **The list is sorted by provider and then model name**: comparison ignores case, but **grouping does not** (provider ids are case-sensitive, so `Beta` and `beta` are two routes and are never merged). Comparison is by code unit rather than `localeCompare`, so the same configuration lists identically across locales. Sorting and folding are presentation only: array order still decides matching among wildcard entries of equal priority, and edits and deletes still write back by the original index.
- **"Add entry" now puts the new entry first** instead of appending it: its `provider` / `model` are empty and belong where they are most visible, and with a long list appending would force a scroll to find the edit box that just appeared.
- **Each model in the breakdown starts collapsed**: the collapsed row is "model · total tokens · cost", and a click reveals the token count and amount for each of the four billing buckets. A session often spans a dozen models, so leading with the totals keeps the panel scannable the moment it opens.
- **Warning badges stay visible while collapsed** (usage without a period, no matching entry) — they bear on whether the bill is right and should not hide behind a click. Neutral identity badges (peak/off-peak, wildcard entry) fold away with the detail.
- **The pricing panel narrowed to 440px** (from 560px), with the schedule form re-laid out: **timezone and public holidays share one row, peak weekdays get a row of their own**. That is not cosmetic — the seven weekday buttons need 214px, and squeezing them into one column of a two-column grid pushes the panel's width floor above 460px; on their own row the floor drops back to the four-column price table (about 380px).

<h3 id="en-v0.5.0-fixes">Fixes</h3>

- **A collapsed card had a blank lower half**: the badge container is `display:inline-flex`, so with zero badges it still generated a line box (roughly one line plus its 6px top margin); with a collapsed card down to an 18px header, that blank band took nearly half the height and made the header look off-centre. Badges are now collected into an array and **the container is only rendered when there is at least one**.
- Two more causes in the same place: the header used `align-items:baseline` while the caret is `inline-flex` (a baseline-aligned inline-flex uses its bottom edge as its baseline, inflating the row and pushing the text up), and the amount used to hug the right edge via the header's `space-between`, which was lost when the header became a button. The header now centres vertically, the caret is `flex`, and the model name takes `flex:1` with an ellipsis while the amount keeps `flex:none` and lines up on the right.
- **A provider row showed only CNY**: a provider accumulated only the display currency, so a provider that had **only ever run a USD route** summed to zero and rendered as `¥0.00`. Each provider now accumulates per currency and follows the same rule as the total.
- Removed **duplicate CSS rules** for `.tf_model` / `.tf_cardAmount` (the later, older copies were overriding the new ones).

<h3 id="en-v0.5.0-docs">Documentation and internals</h3>

- **The compatibility check now extends to DSH `0.2.1-rc.2`**: every contract surface this plugin depends on was re-audited across the seven tags of the 0.2.1 line (`alpha.1`–`alpha.5`, `rc.1`, `rc.2`) and all were unchanged (`Menu`/`Button`'s `.tsx` files are byte-identical between the two releases). The 0.2.1 line brings two **visual** boundaries: the built-in stats pills split into one dock entry each (`activity` / `usage`), and the pill corner radius moved from `999px` to `var(--dsw-radius-sm)` (8px). The first does not affect this plugin (the dock container still owns the row layout and the 12px gap between entries); the second is **deliberately not followed** — `--dsw-radius-sm` is already 8px on `0.2.0-rc.2`, so it cannot serve as a version marker, and `latest` is still `0.2.0-rc.2` (fully round), where switching to 8px would diverge from the built-in pills in the same row. The method and findings are in [`docs/dsh-integration.md`](../dsh-integration.md).
- **The built-in pricing now has a single source**: entries are derived from `DEEPSEEK_BUILTIN_MODELS`, the price blocks appear once, and the entry note states that one entry covers both the API-key and the account route. **This is not new coverage** — the account route already matched through the provider alias at 0.4.0; this only single-sources the data and says so in the entry note shown in the panel.
- The README's currency and breakdown sections, plus the three new `docs/configuration.md` sections ("Folded by provider", "The breakdown folds per model", "How the schedule form is laid out"), record the behaviour above along with the reasoning behind each decision.

<h3 id="cn-v0.5.2">修复</h3>

- **只写规则、还没写任何条目的文件存不下去**：编辑器把「一条条目都没有」当成错误拦下，服务端也要求条目表非空。但文档自己把「先建规则、再挂到条目上」写成了正常操作顺序——于是全新安装时想先建一条规则，只能先造一条用不上的条目。现在空的条目表是合法输入（等于不加任何条目），**内置价目与插件配置层照常生效**；要回到纯内置价目仍用「恢复内置价目」。非数组仍然直接报错——那是形状问题，不是「暂时空着」。
- **连点两次「保存」可能失败（Windows）**：两次并发保存会把临时文件 `rename` 到同一个目标，而 Windows 上 `rename` 到一个正被另一个写者占用的目标是 `EPERM`（POSIX 的 rename 是原子替换，Windows 不是）。写盘现在排队串行，每次调用仍拿到属于自己那次的结果，一次失败也不会卡住后续写入；临时文件名另外补了随机后缀。
- **状态版本的进位会重叠**：表指纹是 32 位哈希（上界 4294967295），而进位基数只取 1e9，约 77% 的指纹大于它。不取模时「折叠版本 3 + 指纹 1e9+5」与「折叠版本 4 + 指纹 5」会算出同一个 `stateVersion`，检查点因此不失效、历史样本按旧表冻结。现在先对基数取模再相加。
- **节假日数据不完整时会静默算错**：数据文件缺 `sets` 段时，内置的 `cn` 引用会解析成「没有节假日」，高峰判定悄悄退化成纯工作日（2026 年春节会被按高峰计）。现在这种情况直接拒绝装载并报错，而不是继续跑。
- **紧凑 token 会显示成 `1000K`**：999 950 在 K 档四舍五入后进位成 1000K，同一数量级现在显示 `1M`。
- **只读选择器的箭头与取值区共用同一个无障碍标签**：屏幕阅读器会读出两个同名控件，键盘也多一个停靠点。箭头改为从可访问性树与 Tab 顺序中移出（鼠标点击仍可展开）。
- 未定价（没有匹配到价目条目）的用量行，其时段兜底由 `peak` 改为 `flat`——与 `tariffOf` 的语义一致：没有条目就没有时段可判，不该说成高峰。

<h3 id="cn-v0.5.2">升级说明</h3>

- 状态版本的计算方式变了，因此**升级后首次打开旧会话会重新折叠一次历史**（数秒），数字不变——这次改动只是让版本号真正唯一，折叠语义没动。
- 两个已知口径**本次未变**，用的时候留意：价格字段写成 YAML 空值或 JSON `null` 会被当成 **0**（即免费）；条目的 `provider` 留空等于写成 `*`，即对所有供应商生效。这两处收紧会让以前能加载的文件开始报错，因此留给下一个改动较大的版本。

<h3 id="cn-v0.5.2">内部</h3>

- 清掉没人调用的 `zeroBuckets` / `addBuckets`（host 与浏览器各有自己在用的副本）、7 个死样式键与 6 条孤儿 CSS 规则、以及一个悬空导出。
- 客户端的假期回归用例改用随包发布的真实数据（`data/cn-holidays.json` + 内置调度），不再内联手写假期：手写只能证明两侧实现同构，证明不了数据文件与内置调度挂得上。
- 测试：pricing 61、host 36、client 111、进程级 8。

<h3 id="en-v0.5.2">Fixes</h3>

- **A file with rules but no entries could not be saved**: the editor treated "no entries at all" as an error and the host required a non-empty entry list. But this document itself calls "create the rule first, attach it to an entry later" a normal order — so on a fresh install, creating a rule first meant fabricating a throwaway entry. An empty entry list is now valid input (equivalent to adding no entries) and **built-in pricing plus the plugin config layer still apply**; "Restore built-in pricing" still returns you to purely built-in pricing. A non-array is still rejected outright — that is a shape error, not "temporarily empty".
- **Pressing "Save" twice in a row could fail (Windows)**: two concurrent saves renamed their temp files onto the same target, and on Windows renaming onto a target another writer holds returns `EPERM` (POSIX rename is an atomic replace; Windows is not). Writes are now queued and serialised, each call still receives the result of its own write, and one failure no longer blocks later writes; temp names also gained a random suffix.
- **The state-version carry could overlap**: the table fingerprint is a 32-bit hash (up to 4294967295) while the carry base is only 1e9, so about 77% of fingerprints exceed it. Without a modulo, "fold version 3 + fingerprint 1e9+5" and "fold version 4 + fingerprint 5" produced the same `stateVersion`, so checkpoints never invalidated and historical samples stayed frozen against the old table. The fingerprint is now reduced modulo the base before being added.
- **Incomplete holiday data used to be silently wrong**: with the `sets` section missing, the built-in `cn` reference resolved to "no holidays" and the peak decision quietly degraded to plain weekdays (the 2026 Spring Festival would have been billed as peak). That now refuses to load and reports an error instead of running on.
- **Compact tokens showed `1000K`**: 999,950 rounds up to 1000K in the K tier; the same magnitude now reads `1M`.
- **The read-only selector's chevron shared the value area's accessible label**: screen readers announced two identically named controls and the keyboard had an extra stop. The chevron is now out of the accessibility tree and the tab order (still clickable with a mouse).
- An unpriced usage row (no matching entry) now falls back to `flat` for its period instead of `peak`, matching `tariffOf`: with no entry there is no period to judge, and it should not be called peak.

<h3 id="en-v0.5.2">Upgrade notes</h3>

- The state-version formula changed, so **the first time you open an existing session after upgrading it re-folds its history once** (a few seconds); the numbers do not change — this only makes the version genuinely unique, the folding semantics are untouched.
- Two known behaviours are **deliberately unchanged** in this release; keep them in mind: a price field written as a YAML empty value or JSON `null` counts as **0** (free), and leaving an entry's `provider` blank equals writing `*`, i.e. it applies to every provider. Tightening either would make previously loadable files start failing, so both are left for a larger release.

<h3 id="en-v0.5.2">Internals</h3>

- Removed the unused `zeroBuckets` / `addBuckets` (the host and the browser each have their own copy in use), seven dead style keys, six orphan CSS rules, and one dangling export.
- The client's holiday regression test now uses the packaged real data (`data/cn-holidays.json` plus the built-in schedules) instead of an inline hand-written holiday list: an inline list only proves the two implementations mirror each other, not that the data file and the built-in schedule connect.
- Tests: pricing 61, host 36, client 111, 8 process-level.
